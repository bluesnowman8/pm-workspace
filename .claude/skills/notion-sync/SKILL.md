# 前提
- **Notion は読むだけ**。Notion のページは絶対に編集しない。
- **使うのは claude.ai の Notion コネクター**（ツール名 `mcp__<ID>__notion-search` / `notion-fetch`。遅延読み込みなら ToolSearch で `notion-search` を探して読み込む）。
  - セッション開始時に「plugin:Notion:notion が未認証」と出ることがあるが、これは**別のプラグイン版で、使わない**。この表示だけで「Notion が未認証・同期できない」と判断・報告しない。
  - 「接続できない」と言えるのは、claude.ai コネクターの notion-search を実際に呼んで失敗したときだけ。
- 役割分担：ユーザーは日中 Notion の週次ページに書き込む（入力元）。業務一覧・優先度・依頼の管理は pm-workspace が正。
- 取り込まないもの：
  - 電話番号、URL（Teams・SharePoint・社内システム・Web）。リンクは表示テキストだけ残す
  - 画像・PDF などの添付
  - 「改善案」「隙間時間で」「備忘」「Archive」「教訓」「美野さん引継ぎフォルダ」「Tips」「コミュニケーション フレームワーク」の中身
- 対象は曜日タブ（Mon.〜Fri.）と「次週」「長期」「月次」タブ、ページ下部の「10月PJ」「スケジュール」「振り返り面談」。

# 依頼の目印（Notion での書き方）
ユーザーは、人に渡した業務を次の形で書く。この形の行は「依頼」として機械的に拾う。
```
→市村さん ZP21組込数をSAPファイルに追加 〆10/16
→法人 ノート在庫販売計画の更新 〆10/16 確10/14
```
| 記号 | 意味 | 省略したとき |
|---|---|---|
| `→名前` | 依頼先（必須。行頭、チェックボックスの直後） | — |
| `〆日付` | 期限 | 自動登録しない（確認待ちに入れる） |
| `確日付` | 次回確認日 | 2段階で確認する：期限の前営業日に「事前確認」、期限の翌営業日に「完了確認」 |

- 日付は `MM/DD`。年は今日以降でいちばん近い日付になるように補う。
- 営業日は土日・日本の祝日を除く日（Notion の曜日タブに「祝日」とある日も除く）。
- `確` を省略した依頼の次回確認日は、まず期限の前営業日にする。それが今日以前になる（依頼が期限の直前だった）場合は、事前確認を省いて期限の翌営業日にする。
- 目印のない書き方（「〇〇さんに依頼済み」「回収」「待ち」など）は、今までどおり確認待ちに入れる。

# 手順
1. **今週のページを探す**：今週の月曜日を `YYYY/MM/DD` にして notion-search で「`YYYY/MM/DD Mon.`」を検索し、path が「Memo / Work / Weekly Plans」で、タイトルがその日付で始まるページを使う。見つからなければ `/Tasks/notion-sync.md` の同期ログに「今週の週次ページが見つからない」と書いて終わる。
2. notion-fetch でページを読む。
3. **スナップショットを作る**：チェックボックス項目を1行ずつ次の形に直す。
   ```
   - [x] Thu/PM 16時～ 新製品開発会議 > 週次検証報告 更新
   - [ ] Fri/AM 週次更新 > 在庫状況把握 > アラート
   - [x] Thu/PM B/DA5-C7HIGA-08S Secured Core Level問題 法人からの回答回収（メモ: 法人もSCL2でOK）
   ```
   - 先頭にタブ名と AM/PM（無ければタブ名だけ）を付ける
   - 入れ子は親の項目を ` > ` でつないで1行にする（3階層まで。それより深いものは親の行にまとめる）
   - 中身が空のチェックボックスは無視する
   - チェックボックスではない箇条書き（結果のメモ）は、直前の項目の末尾に `（メモ: …）` で付ける
4. **前回と比べる**：`/Tasks/notion/YYYY-Wxx.md`（前回のスナップショット）と比べて差分を出す。
   - 追加された項目／`[ ]` から `[x]` になった項目／メモが付いた・変わった項目／消えた項目
   - 差分がなければ `/Tasks/notion-sync.md` の「最終同期」だけ更新して終わる（ほかのファイルは触らない）
   - 前回のスナップショットが無い場合（週の最初の同期）は全項目を「追加」として扱う。ただし todo.md・delegated.md・done/ に既にあるものは除く
5. **差分を振り分ける**。todo.md・delegated.md の既存項目との対応は、案件名・キーワード・出典で判断する。対応が曖昧なら推測で更新せず、確認待ちに入れる。

   | 差分 | 自動で反映してよいこと | 確認待ちに入れること |
   |---|---|---|
   | 新しい作業項目（自分がやるもの） | todo.md の P? に登録する（`提案:` と `出典: Notion週次 MM/DD(曜)` を付ける） | —（P? は /start-day・/prioritize で決めるので、確認待ちには入れない） |
   | 目印（`→名前`）と期限（`〆`）がそろった依頼の行 | delegated.md に新しい ID で登録する（下の「依頼の自動登録」に従う） | 依頼先が /Context/people.md に無ければ、その追記案 |
   | 目印はあるが期限（`〆`）が無い、または期限が過去の日付の行 | — | delegated.md への登録案（期限を質問する） |
   | 目印のない、人に頼んだことが分かる記述（「〇〇さんに依頼済み」「回収」「待ち」など） | — | delegated.md への登録案（依頼先・期限・次回確認日の案） |
   | 目印付きの依頼の行が `[x]` になった、または消えた | 今日の Daily Note に記録する | 依頼を閉じること／取り下げかどうかの確認 |
   | todo.md にある項目が `[x]` になった | 今日の Daily Note に「完了（Notion）」として記録する | 完了扱いにして done/ へ移すこと |
   | 依頼の相手から返事・成果物が来たことが分かるメモ | delegated.md の「経緯」に1行追記する | 依頼を閉じること、状態の変更 |
   | 期限・日時が分かる記述 | — | 期限の設定・変更 |
   | 項目が消えた | — | 完了か取りやめかの確認 |

   **依頼の自動登録**（目印と期限がそろった行だけ。ユーザーの確認は不要）：
   - delegated.md に同じ依頼（依頼先と内容が同じ）が既にあれば登録しない。期限・確認日の書き換えがあっても自動では変えず、確認待ちに入れる
   - ID は `/Tasks/notion-sync.md` の「最後に振った番号」の D ＋1（番号は再利用しない。999 の次は D-1000）
   - 書式は /Tasks/README.md に従う。依頼日は行が追加された日、状態は「依頼済み」、経緯の1行目は `YYYY-MM-DD 自動登録（Notion週次 MM/DD(曜) の目印）`
   - 案件名は内容から判断する。判断できなければ `[共通]` とし、経緯に「案件は要確認」と書く
   - 次回確認日は上の「依頼の目印」の決まりで入れる
   - 同じ内容が todo.md にあっても自動では消さない（統合するかを確認待ちに入れる）
   - `/Tasks/notion-sync.md` の「事後報告」に1行追加する（次の朝・昼・夕の報告でユーザーに伝えるため）

   **確認日の繰り上げ**（すべての依頼。差分が無くても毎回確かめる）：
   - 次回確認日が期限以前（事前確認）のまま期限を過ぎていたら、次回確認日を期限の翌営業日（完了確認）に変える。経緯に `YYYY-MM-DD 期限を過ぎたため完了確認に切り替え` と書く
6. **書き込む**：
   - スナップショットを `/Tasks/notion/YYYY-Wxx.md` に上書き保存する（先頭に取得日時とページのタイトルを書く）
   - `/Tasks/notion-sync.md`：
     - 「最終同期」を更新する
     - 「確認待ち」に追加する（同じ内容は重ねない。番号は「最後に振った番号」の Q ＋1。再利用しない。999 の次は Q-1000）
     - D・Q の番号を新しく振ったら「最後に振った番号」を更新する
     - 「事後報告」に、自動登録した依頼を1行ずつ追加する（`D-xxx 依頼先：内容（〆MM/DD・次回確認 MM/DD）`）。朝・昼・夕の報告で伝えたら消す
     - 「同期ログ」の先頭に、今回の差分の要約を1〜3行で書く（今週分だけ残し、前の週の分は消す）
   - 今日の Daily Note があれば、「記録」の下の「### Notion からの更新」節（無ければ「決定事項・メモ」の前に作る）に追記する。`---` より上にある「今日のトップ5」「今日確認する依頼」「その他のタスク」は書き換えない。ノートが無ければ作らない（/start-day が作る）
   - その日に新しく登録したタスク・依頼は、今日の Daily Note の「## 今日追加されたタスク」（`---` のすぐ上。無ければ作る）にも1行ずつ足す。書式は `- [ ] **タスク内容** ― 追加 HH:MM・P?（提案 P2）・期限・案件名`。期限が今日以前なら行頭に 🔴 を付ける。週の最初の同期で、前の週から引き継がれただけの項目は入れない
   - todo.md・delegated.md を変えたら /Tasks/dashboard.md も同期する（件数と「要対応」。確認待ちの件数も載せる）
7. **定期実行のとき**はユーザーに質問しない（確認待ちに入れるだけ）。今日が祝日で、`/Tasks/notion-sync.md` の「最終同期」が今日の日付なら、何もせずに終える（祝日の同期は1回だけ）。ただし、次のどれかがあれば PushNotification で一言通知する（ツールが無ければ最後の出力に書くだけ）：
   - 期限が今日・明日の新しい項目
   - 依頼を自動登録した（「依頼を登録：市村さん ZP21組込数（〆10/16・次回確認 10/15）」のように、依頼先と内容を入れる）
   - 依頼の相手から返事・成果物が来た（予約送信が記録されている依頼なら「予約送信を取り消してください」と添える）
   - 確認待ちが10件を超えた
8. git commit はしない。変更したファイルの一覧を最後に出力する。
