# pm-workspace

PM業務の情報をすべてこの1リポジトリに集約し、Claude Code と協働するための個人ワークスペース。
参考: 「生成AI協働型 PM業務設計ガイドライン：個人フォルダー構成と情報管理手順」

## この仕組みで解決すること
要件の原文と対応表は [docs/requirements.md](docs/requirements.md)。
| 困っていること | 仕組み |
|---|---|
| 自分の業務一覧を把握し続けられない | すべての業務を `Tasks/` に集約し、`Tasks/dashboard.md` で一覧する。会話やメモに業務が出てきたら AI が必ず登録する |
| 人に渡した業務の進捗確認を忘れる | `Tasks/delegated.md` に「次回確認日」付きで登録。確認日が来たら `/start-day` で AI が知らせ、確認メッセージの下書きまで作る |
| 優先順位付けを省いてしまう | 優先度（P1〜P4）の無いタスクを残さない。毎朝 `/start-day` で「今日のトップ3」を決めないと始まらない流れにする |

## 初回セットアップ（Claude Code デスクトップアプリ）
1. このリポジトリをPCに clone する（GitHub Desktop の「Clone a repository」か、`git clone https://github.com/bluesnowman8/pm-workspace`）
2. Claude Code デスクトップアプリで、clone したフォルダーを作業フォルダーとして開く
3. 入力欄に `/inventory` と入力して、今抱えている業務と人に渡している業務をすべて登録する（質問に答えていくだけ）
4. AI が変更したファイルを確認し、問題なければコミットする（アプリの差分表示か GitHub Desktop で確認）

## 毎日の流れ
| タイミング | やること | 入力 |
|---|---|---|
| 朝 | 今日のノートを作り、確認日が来た依頼・期限切れ・未判断のタスクを片付け、トップ3を決める | `/start-day` |
| 日中 | 今日のノートの「決定事項・メモ」に一行ずつ書く。人に頼んだら「〇〇さんに△△を依頼」と書く | （ノートに書くだけ） |
| 日中 | 人に何かを頼んだ直後に登録しておく | `/delegate 〇〇さんに△△を依頼、期限は金曜` |
| 日中 | 全体を見たいとき | `/dashboard` |
| 夕方 | メモからタスク・依頼を拾って一覧を更新し、コミット | `/sync-tasks` |
| 金曜 | 1週間の振り返りと優先度の見直し | `/weekly-review` |
| 月1回 | 業務の棚卸し | `/inventory` |

スキル名を覚えていなくても、「朝の準備をして」「〇〇さんに頼んだ件を登録して」のように普通に頼めば AI が該当する手順を使う。

## スキル一覧
| コマンド | 内容 |
|---|---|
| `/start-day` | 朝の業務開始。今日のノート作成、確認日が来た依頼・期限切れ・未判断タスクの提示、トップ3の決定 |
| `/inventory` | 業務の棚卸し。質問に答えて、抱えている業務と渡した業務をすべて登録 |
| `/delegate` | 人に渡した業務を、依頼先・期限・次回確認日付きで登録 |
| `/follow-up` | 渡した業務の進捗確認。確認メッセージの下書き作成と、返事の記録 |
| `/prioritize` | 未判断のタスクや多すぎる P1 を、重要度と緊急度の質問で整理 |
| `/dashboard` | 業務一覧のダッシュボードを最新化して全体像を報告 |
| `/sync-tasks` | メモ・議事録から新しいタスク・依頼・状態変化を拾って一覧を更新 |
| `/weekly-review` | 週の振り返りと優先度の見直し |
| `/prepare-meeting` | 案件の定例会議資料のたたき台を作成 |

新しいスキルは、定型作業をやり終えた直後に「今の作業をスキル化して」と頼んで追加する。

## 構成
| フォルダー | 役割 |
|---|---|
| `Daily Notes/` | 週別・日別の作業ログ。日常メモの起点 |
| `Projects/` | 案件ごとの資料・議事録・障害記録 |
| `Tasks/` | 業務一覧（ダッシュボード・自分のタスク・渡した業務） |
| `Context/` | 関係者・略語・文体ルールなどの暗黙知 |
| `Inbox/` | 会議・チャットの要点や、PDF化した資料の一時置き場 |
| `.claude/skills/` | 定型業務のスキル（スラッシュコマンド） |
| `docs/` | 要件（`requirements.md`）と試験運用の手順（`trial-run.md`） |

AIへのルールは `CLAUDE.md` にある。構成もルールも、使いにくければ変えてよい（変えたら CLAUDE.md と各 README.md も更新する）。

## 注意
- 必ず private のまま運用する。業務資料を置く前に会社の情報管理ルールを確認すること。
- 置けない情報は「概要と原本の置き場所」だけを Markdown で書く。
- AI が変更した内容は差分を確認してからコミットする。
