# このツールに求めること（要件）

pm-workspace を作った目的と、ukiyono さんが求めていることの記録。
仕組みを変えるときは、ここに書いた要件を満たし続けているかを必ず確認する。

## 1. 原文（いただいた言葉そのまま）

| 日付 | 原文 |
|---|---|
| 2026-10-05 | 上記の動画を参考にしてプロジェクト管理を行いたい／計画案を出して／githubに別リポジトリを作成して管理することを想定している |
| 2026-10-05 | 動画の内容は以下のようになっているものとして進めて。内容を全て確認すること。（→「生成AI協働型 PM業務設計ガイドライン」を共有） |
| 2026-10-05 | 基本的にGUIのClaudeCodeで運用する想定。 |
| 2026-10-05 | 業務上苦心していることは、以下。これが解決する運用となるような仕組みにして。自分の業務一覧を把握し続けられないこと。一度他の人へ渡した業務の進捗管理を忘れてしまうこと。優先順位の決定を省いてしまうことがあること。 |
| 2026-10-08 | 上記前提の上で、試験運用開始。テストファイルを作成して。ソースはNotionの今週の週次ページを用いること |

## 2. 要件と、それを満たす仕組み

| # | 要件 | 仕組み | 置き場所 |
|---|---|---|---|
| R1 | 自分の業務一覧を把握し続けられるようにする | すべての業務を Tasks に集約し、ダッシュボードで一覧する。会話・メモに業務が出てきたら AI が必ず登録する。月1回の棚卸し | `Tasks/dashboard.md`・`Tasks/todo.md`・`/inventory`・`/dashboard`・`/sync-tasks`・CLAUDE.md「業務一覧（課題1）」 |
| R2 | 他の人へ渡した業務の進捗管理を忘れないようにする | 渡した業務を「次回確認日」付きで登録し、確認日が来たら朝に AI が知らせる。確認メッセージの下書きも作る | `Tasks/delegated.md`・`/delegate`・`/follow-up`・`/start-day`・CLAUDE.md「渡した業務（課題2）」 |
| R3 | 優先順位の決定を省かないようにする | 優先度（P1〜P4）の無いタスクを残さない。毎朝「今日のトップ3」を決める。P1 が4件以上なら指摘する | `/start-day`・`/prioritize`・CLAUDE.md「優先順位（課題3）」 |
| R4 | GUI の Claude Code（デスクトップアプリ）で運用する | clone したフォルダーをデスクトップアプリで開き、スラッシュコマンドか普通の依頼文で使う | `README.md`「初回セットアップ」「毎日の流れ」 |
| R5 | GitHub の別リポジトリで管理する | private リポジトリ `bluesnowman8/pm-workspace` | このリポジトリ |
| R6 | 参考動画（ガイドライン）の考え方に沿う | 1フォルダー集約、Daily Notes / Projects / Tasks、CLAUDE.md・Skills・README 索引、人間と AI のギャップ対策（Context / Inbox） | リポジトリ全体 |
