# Tasks（索引）

自分の業務をすべてここに集約する。「ここに無い業務は存在しない」状態を保つ。

| ファイル | 中身 |
|---|---|
| `dashboard.md` | 業務一覧のダッシュボード。まずここを見る（AI が更新する） |
| `todo.md` | 自分が持っているタスク（優先度別） |
| `delegated.md` | 他の人へ渡した業務（次回確認日付き） |
| `done/YYYY-MM.md` | 完了したタスク・依頼の月別アーカイブ |
| `notion-sync.md` | Notion 週次ページとの同期状況と「確認待ち」（AI が判断を保留しているもの） |
| `notion/YYYY-Wxx.md` | Notion 週次ページのスナップショット（差分を取るためのもの。手で編集しない） |

## 優先度
| 優先度 | 意味 | 扱い |
|---|---|---|
| P1 | 重要かつ緊急 | 今日〜明日中にやる。8件まで（9件以上で指摘） |
| P2 | 重要だが緊急ではない | 日時を決めて計画的に進める |
| P3 | 緊急だが重要ではない | 短時間で片付けるか、人に渡す |
| P4 | 重要でも緊急でもない | やらない・後回し候補 |
| P? | 未判断 | その日のうちに P1〜P4 に決める |

## todo.md の書式
```
- [ ] [案件名] タスク内容 | 期限: YYYY-MM-DD | 状態: 未着手/進行中/待ち(誰の何を) | 出典: ファイルパス
```
タスクは優先度ごとの見出し（## P1 など）の下に置く。
P? のタスクには、AI の案を `| 提案: P2（理由）` の形で末尾に付けてよい。優先度が決まったら「提案」を消して該当の見出しへ移す。

## delegated.md の書式
```
### D-001 [案件名] 依頼した内容
- 依頼先: 〇〇さん
- 依頼日: YYYY-MM-DD
- 期限: YYYY-MM-DD
- 次回確認日: YYYY-MM-DD
- 状態: 依頼済み / 進行中 / 遅延 / 確認待ち（自分が成果物を確認する番）
- 予約送信: YYYY-MM-DD HH:MM（Teams で確認メッセージを予約したときだけ書く。送信・取り消しが済んだら消す）
- 経緯:
  - YYYY-MM-DD 依頼した（どの場で・何を渡したか）
  - YYYY-MM-DD 確認した結果
```
- ID は D-001 から連番。完了したら `done/YYYY-MM.md` へ移す。
- 番号は再利用しない（閉じた依頼・取り下げた依頼の番号も欠番のままにする）。次の番号は `notion-sync.md` の「最後に振った番号」＋1。念のため `delegated.md` と `done/` にある最大の番号とも比べ、大きいほうを使う。振ったら「最後に振った番号」を更新する。
- 番号は3桁でゼロ埋めする。999 の次は D-1000 と、桁を増やして続ける。
- 確認待ちの番号（Q-001〜）も同じ決まり。確認待ちは解決すると表から消えるので、次の番号は必ず「最後に振った番号」から数える。
- 次回確認日は、期限の半分の時点を目安にする（期限が無ければ3営業日後）。
- Notion に目印（`→名前 内容 〆期限`）で書いた依頼は、/notion-sync が確認なしで登録する。`確日付` を省略したものは2段階で確認する：
  - 事前確認：期限の前営業日（次回確認日が期限以前のあいだは「事前確認」）
  - 完了確認：期限の翌営業日（事前確認を記録したとき、または期限を過ぎたときに、次回確認日をここへ進める）
- 「今日まだ確認していない依頼」とは、次回確認日が今日以前で、経緯に今日の日付の行が無いものを指す。
